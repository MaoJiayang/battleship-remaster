# 项目地图

## 技术与执行链路

- 原生 JavaScript 模块、HTML、CSS，使用 Vite；没有前端组件框架或独立游戏引擎。
- `index.html → src/main.js → initGame()`：加载样式、棋盘与舰船、事件、武器系统和帮助内容。
- `game.js` 负责部署、模块级状态、回合调度、手机视角、结算面板等；这是跨功能改动最集中的文件。
- 状态大致为 `SETUP → PLAYING → END`；当前回合还通过敌方棋盘的 `pointerEvents` 控制玩家输入。
- `legacy/` 是历史单文件；日常功能修改以 `src/` 为入口。`dist/` 是构建产物。

## 当前玩法依据

棋盘为 11×11，每方五艘舰，共 14 个舰体格、27 点总血量。各舱独立血量，全舰各舱归零才沉没。

| 代号 | 舰种 | 长度 | 每舱血量 | 存活时提供的基础能力 |
| --- | --- | --- | --- | --- |
| CV | 航空母舰 | 4 | 2 | 空袭 |
| BB | 战列舰 | 4 | 3 | 主炮 3 伤档位 |
| CL | 轻巡洋舰 | 3 | 1 | 主炮 2 伤档位 |
| SS | 潜艇 | 1 | 2 | 主炮 2 伤档位、水听 |
| DD | 驱逐舰 | 2 | 1 | 水听 |

阵营学说会修正上述能力。保持属性定义与能力计算共用，避免在 UI 或 AI 中再写一套规则。

- **主炮 AP**：单点打击，溢出伤害可向同舰相邻舱传导；本发攻击前已损毁的舱室阻断该方向，左右分别判断，本发新毁舱室仍可继续传导。伤害、传导上限、防御修正由学说决定。
- **空袭 HE**：默认中心和四对角组成 X 型；赤潮使用十字型；绯木的航母沉没后转单点。确认空海域和摧毁舱跳过，受损舱可继续攻击。
- **水听 SONAR**：默认 3×3；仅统计 `!cell.hit` 的舰体格。有信号时显形中心或最近接触，其余未暴露格标疑似；无信号时清除未处理海域。接触不扣血，已接触或受损舱不会因后续清海被覆盖。
- **残局信息**：最后一舰阶段继续普通回合；2026-10-25 已按用户要求移除自动追击、周期接触区及对应 AI 位置约束。主动水听照常工作，其他盘外信息模式暂未引入。
- **无效行动**：`battle/ActionRules.js` 共用前置校验，只拒绝依已有可见状态及观测证据就能确定无效的行动；血量变化有效，范围中心已处理但外围可打有效。依赖隐藏结果的水听仍正常执行、消耗回合，即使没有格子改变。正信号证据 `sonarEvidence` 来自公开水听事件；完整证据仍落在扫描疑似区时可证明重复扫描无效，新命中／排除后可以恢复扫描。不得用隐藏舰位或结算后差分决定是否免费拒绝。
- 实战胜利由 `game.js/checkWin()` 全灭判定；浏览器当前没有赛规卡所说的统一 150 手上限。模拟默认 400 手，循环赛示例 320 手，房间默认 150 手。

七个虚构阵营的公开名称位于 `factions.js`：蓝钢 `us`、绯木 `ijn`、狮心 `rn`、铁雾 `km`、鸢尾 `fn`、苍鹰 `rm`、赤潮 `sn`。内部历史代号继续用于数据与美术索引；玩家文案使用公开名称。

`doctrines.js` 提供 `getAPDamage/getAPMaxPenetrations/getHEProfile/getSonarProfile` 和防御修正。它同时包含机制参数及 AI 武器偏好，两者对模拟结果的影响需要分别判断。

## 武器结算与视野

实战执行：

```text
玩家点击 / aiTurn
→ 构建攻击方上下文
→ WeaponService 校验武器和目标
→ APWeapon / HEWeapon / SonarWeapon
→ resolveHit / resolveSonar 修改纯数据并返回事件
→ BattleRenderer 更新格子、特效、日志、声音
→ 统计与对局记录、状态刷新、胜负及回合推进
```

- 事件种类：`CELL_UPDATE / SHIP_UPDATE / LOG / EFFECT`，定义在 `WeaponTypes.js`。
- 真实结算格包含 `hit/shipId/segmentIndex`，舰船包含分舱 `hp`。
- AI 认知格编码：`0未知 / 1未中 / 2命中或接触 / 3摧毁 / 4疑似 / 5沉没`，见 `ViewState.js`、`aiCore.js`。
- 视觉层单独保留 `contact`，AI 输入将其并入命中；评估血量或信息价值时注意这个表达边界。
- `HitResolver`、`SonarResolver` 保持纯数据结算。武器封装和渲染器还包含音效或 DOM 依赖，不能将整个实战控制器当成服务端引擎。
- 当前界面数字在横轴、字母在纵轴，见 `addCoordLabels()`；CLI 使用行、列数值。赛规卡对界面字母列的描述与画面有偏差，涉及坐标时明确采用哪种约定。

## AI 的实际工作方式

```text
scheduleAiTurn 构建可克隆视野快照并立即请求 Worker
→ AIDecisionEngine.decide
→ 检查己方能力、筛选未沉目标、难度随机分支
→ BeliefState 采样与观测相容的完整舰队配置
→ 枚举主炮、空袭、水听候选，过滤已用水听中心
→ 对称推演己方各舰受威胁程度
→ 信息增益、期望伤害、学说倾向和风险加成评分
→ 同分候选随机选择，记录预计伤害及水听历史
→ Worker 返回，等待动画最低时间后由实战武器执行
```

| 难度 | 信息权重 alpha | 故意随机概率 | 风险权重 | 目标采样 | 对手采样 | 推演步数 |
| --- | --- | --- | --- | --- | --- | --- |
| EASY | 0.4 | 0.6 | 0.1 | 260 | 16 | 1 |
| NORMAL | 0.6 | 0.3 | 0.25 | 550 | 32 | 2 |
| HARD | 0.84 | 0 | 0.46 | 1400 | 80 | 4 |

数值依据为 `difficulties.js` 与 `aiTuning.js`；默认简单。表是接手快照，调参时读取当前源码。

- `BeliefState` 预缓存舰长放置表，以位掩码排除 Miss/Sunk，采样中禁止舰体重叠，并覆盖已命中和摧毁点。
- 已命中、疑似格影响放置权重；最后一舰区域接触会限制候选区域。全未知且无历史先验时使用均匀概率，跳过采样。
- 样本不足时会复制已有样本；采样上限为目标采样数的 20 倍尝试。排查强度或耗时时区分配置样本量、成功独立样本量与退化回退。
- HARD 当前启用 `fastSampling`：旧评分路径用累计概率表和条件拒绝采样替代每次全表扫描，保持原条件分布；实验联合后验用独立提议、整舰队拒绝及对应重要性权重。具体实验及搜索预算见 [AI 实验进度](ai-research.md)。
- 信息增益使用逐格熵近似；水听无信号概率使用边缘概率组合。主炮评分目前未额外计入穿甲收益。
- 风险推演对每步重建置信状态、贪心选行动，并以概率是否大于 0.5 更新模拟视野。推演步数表示这种近似的深度。
- `damageDealtGrid` 是预计伤害记账；检查补刀或有效伤害估计时核对随机分支、接触、传导与实际结果反馈。
- Worker 返回失败时实战回退主线程决策；调试热力图也可在主线程重新采样。不能从“有 Worker”直接推断主线程永不受 AI 影响。

### 历史学习与布阵

- `playerModel.js` 在完成对局时记录玩家按舰长的布阵频率和去重射击格；旧计数每局乘 0.94。
- 聚合画像存于 `hzq_player_model_v1`，输出布阵先验与射击注意热图；没有当前隐藏布阵输入。
- 布阵先验按船长平滑、限制倍率，再以样本数收缩到均匀分布；旧 `BeliefState` 将候选船体各格先验的几何平均乘入抽样权重，与本局合法布局和命中约束共同生成占位概率。旧评分策略据此评估武器，不直接选择历史最热格。
- 射击热图只统计去重射击位置，并非跨局武器偏好模型。稀疏布阵的候选抽样权重为 `1/(1+0.6×船体平均热度)`。当前神经观测未读取这两张历史图；射击图仍通过前置布阵间接改变己方舰队状态，网络第 6 平面则是仅根据本局观测重算的近似占位概率。
- `aiDeployment.js` 随机打乱舰种，枚举合法位置并偏向分散，间距不足时逐步放宽；实战敌舰还轻度避开历史搜索热区。
- 模拟双方分别持有决策实例，隔离伤害和水听历史；模拟入口目前未接入历史玩家画像。

### 轻量网络实验链路

- `neuralObservation.js`：从公平上下文编码 17×11×11 棋盘平面、86 个规则及舰队摘要和 363 个合法动作掩码；只读取己方真实舰队，敌舰只读公开描述。占用概率输入是独立舰艇近似边缘分布，搜索仍采用联合舰队粒子。
- `neuralNetwork.js`：纯 JavaScript 前向计算，支持小卷积＋单层双头交叉注意力和全连接基线；校验协议 `naval-belief-v1` 与物理学说规则指纹。`neuralRules.js` 包含 `ActionRules.js` 的结算语义版本；2026-10-25 取消自动追击后版本为 3、指纹 `4bce9d7c`，含追击的 `27fe331d` 及更早权重均需重新训练验证。旧神经全局末五槽、统一全局第 2–6 槽保留尺寸并固定为零，旧追击上下文不再参与编码。
- `tools/training/neural_model.py`、`train.py`：同结构 PyTorch 训练及权重导出。旧困难 AI 对局仅提供终局价值起步；自对弈搜索访问分布提供策略标签，终局胜负提供价值标签。按交换座位共享的布阵组划分训练/验证集。
- `generate-data.mjs` 多进程生成真实模拟对局，`validate-model.mjs` 比较 JavaScript 与 PyTorch 数值并测单次推理；`selftest.mjs` 检查隐藏信息边界、机制输入、合法搜索和超时退路。
- 搜索决策器只有显式注入 `neuralModel` 时使用网络；`policyTrained=false` 时仅用价值头，保持原后续策略。普通游戏及原 `ai-lab` 入口不自动加载权重；独立 `neural-preview` 构建显式接入冻结直接策略，见下条。阶段成果和验收边界见 [AI 实验进度](ai-research.md#游戏网络首轮实现与验证)。
- `neuralHistory.js` 定义公开攻击事件：相对行动方、回合、武器坐标与能力、攻击前后公开视图，共 258 维；模拟器仅在 `recordPublicHistory=true` 时采集，不读取隐藏目标坐标或血量。`memoryNetwork.js` 支持 16 维 GRU 或历史交叉注意力的增量 JavaScript 推理，`directPolicy.js` 负责公平观测编码、记忆更新、合法动作过滤和直接选招。
- `tools/training/policy-environment.mjs` 以 JSON 行协议批量运行真实模拟器；`memory_model.py` 定义对应 PyTorch 结构，`ppo.py` 采集当前策略轨迹，执行 PPO 自对弈并维护历史对手。`tools/sim/strength.mjs` 以 `candidate.direct=true` 显式测试直接策略，普通游戏及 Worker 不自动加载新模型。
- `#naval-game-policy` 由 Vite 选择：普通构建指向 `gamePolicy.js`，只转发原策略；体验构建指向 `previewGamePolicy.js`。原 `neural-preview` 仍固定旧 GRU/PPO 第 48 轮，当前规则会拒绝它；新增 `unified-preview` 可显式指定当前规则的已训练统一模型与预期哈希，独立输出 `dist-unified-preview/`，简单／中等仍为旧策略。模型来源和标签由构建写入，记录格式、记忆种类、规则、权重哈希及监督轮次／PPO 迭代。主线程和内联 Worker 使用同一入口；`previewPolicyRuntime.js` 按协议创建历史模型或统一模型，在实际成功结算后保存双方历史，出手前捕获能力，重开清空。后台线程不可用时，主线程从已执行的己方记录恢复伤害／水听状态并使用同一个模型，不静默切回旧困难 AI。
- `expert_data.py` 从同一环境采集旧 HARD 实际执行的行动，按完整对局划分训练／验证；历史事件共享存储，局面仅引用当时前缀。`expert_train.py` 用合法行动交叉熵与正常终局价值预热现有 GRU／注意力，保留双集合逐轮指标及权重，再作为 PPO 起点；训练截断只提供行动标签。
- 用户确认旧 AI 只用于冷启动及诊断，`ppo.py` 的训练对手仅为当前神经策略和冻结历史快照；空池直接自对弈。`NeuralSelfPlayEnvironment` 禁止空行动请求程序化 AI 代走，训练与检查点记录 `neural-current-history-v1` 对手协议，恢复拒绝协议不符；旧混合对手结果保留为历史实验，不按此单一诊断选模。
- 历史包含行动方视图，神经观测第 10–15 平面读取对手 `playerViewGrid`；它描述对手对己方舰队的认知，不是敌舰真实布阵。2026-10-24 实际房间水听测试确认双方接口均提供这些标记（`yourWaters=foe.view`），不能仅因读取链路就认定作弊。先前只固定己方攻击视图的差分未固定完整合法输入；自动追击现已整体取消，水听公开观测契约保留。候选仍未通过学说平衡及实战验收。
- `tools/training/ppo_audit.py` 冻结模型采集轨迹，比较采集与重算概率、策略分布及策略／价值／熵梯度；不执行参数更新。跨学说测试通过 `strength.mjs` 的显式 `matchups` 入口进行，逐对阵统计与阵营聚合含义见验证参考。
- 模拟器结果新增 `terminated/truncated`，手数上限归为训练截断，旧 `winner='DRAW'` 字段保留兼容。PPO 截断从该玩家最后的公平观测估值，不固定填 0.5；配对测试若有截断，单一胜率与置信区间不作为有效结论，并报告结果上下界。
- PPO 重置训练环境时显式传学习座位；手数上限按奇偶对齐到下一次该方决策，最多补走一手对手行动。采集器核对末端行动方后才自举，真实制胜仍优先结算；正式模拟规则与网络输入不变。现有正式规模 PPO 训练均未发生截断，旧结果不受此边界修正影响。

### 参数化统一模型原型

- `unifiedObservation.js` 的 `naval-grid-v1` 输入为动态高宽的 22 通道网格、8 个全局量、变长舰船／武器／覆盖偏移及能力变化集合，输出动作数为己方武器数×格子数。当前游戏适配器 `unifiedAdapter.js` 仍按真实 11×11、AP／HE／水听生成合法动作；网络的尺寸支持不代表游戏引擎已改为可变尺寸。
- 武器当前伤害、覆盖、穿透、侦察方式与可用性为主输入；双方舰船—武器依赖通过公开能力的缺舰／单舰／击沉数变化描述输入，不按学说名独热编码，不手工规定优先攻击航母。依赖编译按公开舰队状态与规则指纹缓存，每个策略／训练座位只留当前缓存；己方血量、布局和历史先验仍逐手更新。
- `unifiedNetwork.js` 与 `tools/training/unified_model.py` 对应：共享两层卷积、集合编码、逐格 GRU／时间注意力、按武器覆盖汇聚的共享动作评分、全局胜率头。默认空间／集合／记忆宽度 12／8／8，参数量分别 7014／6830；可选结构元数据 `architecture.widthMultiplier=2` 用于容量对照，旧权重省略时默认 1，加载与恢复校验结构。JavaScript 增量更新历史，参数不含固定棋盘、五舰种槽或三武器输出维数。
- 学说增强使用 `doctrines.js/createDoctrineVariant()` 的不可变参数描述；仅接受七原型的整数参数白名单和范围，保留武器形状及舰船依赖，法国主炮原固定 4 伤可在实验描述中参数化、正式默认仍为 4。`SimulationEngine` 的可选 `config.doctrine` 同时影响实际结算和能力输入，不改全局 `DOCTRINES`。`tools/training/doctrine-variants.mjs` 生成七原始锚点及 31 个单参数邻域变体，共 38 个描述；`policy-environment.mjs` 显式传入目录时才启用，按原型家族内均匀抽样并保留配对参数。增强规则范围为 `cc1fc3bb`，原始仍为 `4bce9d7c`；旧观测拒绝增强，原权重不会自动获得新规则验证范围。
- `unified_data.py` 采集新规则下真实旧 HARD 出招、完整终局及共享历史前缀，按整局分割并保存压缩数值数组；`expert_train.py` 按数据格式显式选择新模型，随后复用 `ppo.py` 的胜负回报、截断自举及历史池。只有显式 `encoding=unified`、统一格式权重及 `direct=true` 才启用新链路；普通游戏与冻结体验包未替换。
- 原型显式支持历史布阵先验及置信度；当前离线模拟没有玩家画像，不能宣称已学会使用这些输入。射击热图继续仅影响部署。r26–r29 的已训练真实规则域为旧 `27fe331d`；当前 `4bce9d7c` 须新采数据与训练，结构测试不授权任意新规则零样本上线。
- `simulation_data.py` 提供不依赖训练框架的 Node 环境客户端、整局划分、源码哈希及原历史协议常量；旧模块保持导入兼容。`unified_inputs.py` 共用 NumPy 批次整理，`unified_data.py` 可在仅有 NumPy 的 CPU 环境采集；`unified_model.py` 在同一数组上转 PyTorch 张量供原 GPU 网络训练。网络、标签、随机协议和数据格式保持，CPU 采集不等于 CPU 训练。

## 联机已有基础

- `arena.mjs`：引擎序列化、恢复、行动验证、人机对战命令行；会话保存到系统临时目录。
- `room.mjs`：双座位、真人或 AI 控制、版本号、轮次验证、动作提交、认输、分座位视野及房间保存。
- `submit()` 检查版本和座位，`viewFor()` 仅公开己方完整舰队和敌方公开信息，结束后才揭示敌舰。
- 房间文件包含双方隐藏布阵。扮演参赛者时依赛规仅用 `status/log`，不读取隐藏房间文件。
- 房间／单人桩序列化保存各方 `sonarEvidence`；历史存档缺此字段时恢复为 `[]`，仅放宽可尝试的扫描，不推断隐藏布局补造证据。房间、模拟、实机武器及神经合法动作掩码共用前置规则，拒绝不推进回合、版本、统计或日志。
- 多人桩创建房间支持 `--ai=search`，仅 HARD、仅 AI 控制座位启用当前统一实验搜索；默认仍为原评分策略。模式存入房间并在分座位视图与状态文本展示，旧房间按默认策略显示。
- 当前浏览器没有房间入口或对战网络传输。网络联机还需围绕房间实现身份绑定、连接管理和恢复，并核对部署阶段如何接入；这些都是后续设计议题。

## 画面、声音与记录

- `shipArt.js` 按阵营、舰种生成内联 SVG，包含不同船体、甲板、炮塔等细节；不是外置贴图系统。
- `ships.css` 负责舰体状态；`base.css` 含基础布局及后续美术、移动端覆盖，改样式时检查后面的同名选择器。
- `BattleRenderer` 生成命中、爆炸、水花、扫描、机群、火箭、浮字与震屏；特效限制在棋盘层内，使用 CSS 动画及定时清理。
- 已有命中音效节流、命中特效数量限制、机群 data URL 缓存等优化。后续性能改动以测量与实际画面为依据。
- `sfx.js` 使用 Web Audio（浏览器音频接口）合成炮声、命中、沉没、飞机、水听、胜负等，带压缩、混响及回声；用户手势后启用音频上下文。
- `matchRecorder.js` 记录动作、目标状态、覆盖统计、伤害、沉船和结局；浏览器存储最多 200 局，可导出，也可经开发服务或文件夹授权落盘。
- `vite.config.js` 的 `/__matchlog` 用于记录落盘；它不是联机对战服务。静态分发环境的落盘能力需另行核实。
